# Freemy SEO 验收

## 本地静态验收

在仓库根目录使用 Node.js 20 或更新版本，安装项目依赖后运行：

```sh
npm test
npm run build
node scripts/check-seo.mjs --dir dist
```

构建会重新生成 `dist` 与 `reports/seo/page-manifest.json`。静态审计以该清单为准，必须针对同一次构建的输出运行；`--dir` 可以指向另一份与该清单匹配的构建目录。审计本身不访问网络，也不修改构建目录。结果写入 `reports/seo/static-audit.json` 和 `reports/seo/summary.md`，每次运行会覆盖上次的报告；报告不应放进 `dist`。

命令返回值为 0 表示没有错误，非 0 表示审计有错误或无法完成。报告中的 `errors` 必须全部解决后才通过；`warnings` 需要人工审阅，但不会使命令失败。标题超过 60 个字符或描述超过 160 个字符会提示，长度按 Unicode 字符统计，阈值只是审阅提示，不代表搜索引擎固定的显示宽度限制。

审计覆盖：

- 每个清单页面存在，标题和描述各有一个、非空且不与其他页面重复；canonical 唯一并与清单中的正式地址一致。已有的 Open Graph 标题、描述及地址须与页面一致，分享图须是存在的站内绝对地址。
- 可索引页面的英文、简体中文和 `x-default` 均指向同一内容的正确语言页面，两个页面分别声明一致的对应关系；非索引页面须声明 `noindex`，且不发布语言替代链接。
- sitemap XML 格式及地址集合与清单匹配，不得重复或包含未列为可索引的页面；检查其中引用的站内图片。`robots.txt` 应允许抓取并声明正式 sitemap。
- 正文中的站内链接按页面地址和 HTML `base` 解析，并忽略查询参数及片段后匹配页面清单和构建产物；外部链接和纯片段链接不在此项检查范围。
- 检查 HTML 直接引用的站内图片、`srcset`、视频封面、图标、样式、脚本和分享图是否存在；Vercel 注入的 `/_vercel/` 资源不要求存在于本地。每个 `<img>` 必须有 `alt`；允许纯装饰图片使用空 `alt`。
- 需要结构化数据的页面须有 JSON-LD，所有 JSON-LD 必须完整闭合且能够解析。探索、类型、主题及合集页的 ItemList 须与正文作品卡片的标题链接按顺序一致；合集索引须与合集卡片一致。列表为空时不得索引，即使清单错误地将其标为可索引也会报错。

`node --test tests/seo-audit.test.mjs` 可单独运行审计器回归测试。测试在临时目录构造站点，涵盖错误 canonical、双语互指、资源缺失、空分类进入 sitemap、`noindex`、robots 和恶意 `</script>` 等情况。

## 仍需单独核验

静态审计不执行页面脚本，不检查外部资源、CSS 内引用或脚本的传递依赖，也无法判断图片内容与 alt 的语义是否准确；这些应在浏览器验收中复核。它也不能证明线上 HTTP 状态、响应头、重定向或真实抓取结果。部署后应在允许的环境中另外检查 `/`、`/zh/`、英文详情页、无效地址、`/en` 和 `/en/` 重定向、带查询参数的地址、`X-Robots-Tag`、线上 sitemap 与分享图，并以搜索引擎工具的实际抓取结果为准。静态通过不代表已经部署或完成线上验收。
