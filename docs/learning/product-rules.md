# Freemy 源码入口与学习增强：产品设计与核验规则

日期：2026-11-16。建议方案，不是已上线功能。

## 1. 当前基础与目标

已检查 `freemyai/website` 提交 `c68db3dff9e67c3957dad042ba725a42d66da266` 的作品卡片、作品样本、目录加载和统计模块。当前卡片保留预览、详情、体验、作者；源码入口需要增加独立数据与渲染规则。当前统计已有 `preview_open`、`experience_open`、`related_click`、`collection_open`、`work_view`、`work_impression`，本轮只扩展学习相关事件，不重做统计系统。

目标路径：发现作品 → 直接体验 → 找到可信源码或说明 → 形成自己的理解。

不变项：品牌、真实预览、中英文、作者归属、直接跳转、现有稳定 work_id/slug、静态构建、SEO 与隐私控制。

## 2. 方案选择

### A. 有链接就显示平台图标
实现快，但会把作者主页、公开但无许可的代码、模型权重或错误仓库误当开源。不采用。

### B. 核验过的源码入口 + 少量可信学习资料
建议采用。公开展示仍轻量；数据层分清“来源关联”和“许可”；有内容才显示入口。

### C. 无源码时自动生成完整技术揭秘
不采用作为默认路径。容易根据画面猜框架、猜架构、猜提示词；一次生成全站文章也没有足够审查基础。

## 3. 源码展示规则

主卡源码入口需要同时满足：

- resource.kind 为 `source_code` 或 `space_code`。
- relation 为 `exact_project`，并有可追溯的一手关联证据。
- match_status 为 `verified`。
- availability 为 `available`。
- license.status 为 `open_source_verified`；有明确许可原文、许可范围与准确标识，且经过复核。
- publication 为 `published`。
- code_scope 明确为 `full_project`、`frontend` 或 `module`；部分公开必须显示“前端源码 / Front-end source”等准确标签，不能声称整个应用开源。

GitHub 或 HF 图标只表示目标平台；“开源”是否成立由以上规则决定，不能由域名决定。

| 条件 | 卡片 | 详情 |
|---|---|---|
| 已核验对应作品，明确开源许可证 | 平台图标 + 源码 | 源码入口、许可证链接、范围、检查时间 |
| 公开可读代码，许可未明确 | 不显示开源图标 | 可显示普通链接：公开代码（许可未明确） |
| 源码可见但有限制性许可 | 不进入开源筛选 | 标明许可限制，链接原文，不自行承诺可商用 |
| HF Protected Space，演示可访问但代码不可读 | 仍为体验入口 | 不作为源码 |
| 只有模型权重或数据集 | 不作为应用源码 | 单独标明模型/数据资源 |
| 社区复刻/上游依赖 | 不作为原作源码 | 可作为明确标注的学习参考，P0 可先不展示 |
| 搜索未找到 | 不显示 | 不标“闭源”；记录本次未找到 |
| 有已发布学习笔记或核验作者说明 | 书本/文档图标 | 指向对应正文或作者文档 |
| 两项都没有 | 保持原作品展示 | 不创建空学习区 |

### 许可细节

- 公共仓库不等于开源；没有明确许可时不能自行授予复用权利。
- SPDX 标识存在，不代表一定是 OSI 开源许可证。限制非商业用途的许可不能简单归入开源。
- GPL/AGPL 不应错误标成“禁止商用”，也不能忽略相应义务；详情只准确显示许可和原文，不自动生成商用保证。
- GitHub API 的 license=null 或 NOASSERTION 表示未得到识别结论，不是“绝对不存在任何许可”的证明。
- 优先检查目标目录/文件是否有单独许可，然后检查父目录、仓库根许可、README 与明确例外。素材、音乐、字体、模型可能使用不同许可。
- 许可证条件复杂或冲突时保持 needs_review，不强行自动判定。
- 仅添加链接和整套源码转载是不同事情；本轮默认不镜像代码、素材或模型，不把 README 整篇搬运。

## 4. 证明“这就是该作品”

优先证据：原站明确源码链接；作者公开帖子明确仓库与演示的对应；仓库 README 指向确切演示；作者域名/账号及源码文件路径、标题、功能相互印证。

不能仅凭：同名、同头像、近似画面、相同技术栈、来自 github.io、某个模型生成声明、第三方汇总帖。

单仓库多作品：主入口定位到具体文件或子目录，详情再提供仓库主页。共享仓库地址是合理的，不能套用现有 demo URL 去重规则把不同作品合并。

保留用户点击用的稳定分支链接，另存审核时的 revision 和永久证据链接。解读中的行号引用应固定 commit，而不是用 main 上会移动的行号。

公开检索受登录、限流或网络影响时记录 blocked/restricted，不能写成“未开源”。

## 5. UI 与交互

### 卡片
预览图仍最大；名称/简介仍是主要文字。作者行右侧或底部操作行最多添加两个学习入口。示意（文本表达，不是已完成设计稿）：

作品名称                    体验作品 ↗
一句准确介绍
作者名称             [GitHub 源码] [学习笔记]

没有源码的卡片可以是：作者名称 + [学习笔记]；没有学习内容则仅显示作者。

- 源码主入口优先级：与作品直接对应的原始项目 > 经过核验的维护版本；更多来源放详情，不堆一排品牌图标。
- 默认小图标配短文字，手机也能理解。纯图标须有本地化 aria-label、键盘焦点和可用提示，不靠 title 提示作为唯一说明。
- 图标视觉约16–18px，点击区域建议40–44px，不小于适用无障碍标准要求；不遮挡预览和体验按钮。
- 使用可追溯许可的本地静态图标，保留来源，不随意抓作者图标 SVG。无需为少量图标加载完整运行时图标库。
- 外链使用真实 a[href]，target=_blank，保留适当 rel 安全设置；没有 JavaScript 也能打开。
- 点击源码不得触发预览弹窗、卡片导航、experience_open 等其他行为；禁止嵌套 a 标签。

### 快速预览
与当前作品同步更新源码与学习入口。每次打开弹窗先清空旧来源；关闭或切换到无源码作品时不得残留上件作品链接。

### 详情
新增稳定锚点 `#source`、`#learning`。首屏仍为预览与体验。后部展示源码范围、许可证、检查时间、阅读起点、作者资料与学习正文。不要把来源详细审查记录全部塞进卡片的 data-work。

## 6. 学习笔记：推荐从少量可信内容开始

三种可选内容：

1. `source_walkthrough`：基于已阅读源码的源码解读。标题“源码解读 / Code walkthrough”。关键技术结论引用具体文件/版本。
2. `author_summary`：基于原作者公开说明的整理。标题“创作说明 / Creator notes”。清楚区分作者说明和 Freemy 补充。
3. `implementation_idea`：没有原作源码时，对类似效果给出的原创实现建议。标题“实现思路 / Implementation ideas”。显著说明“不是原作者实现，不代表原作技术栈”。不自动生成，不作为缺源码的必填替补。

第一版建议 3–5 篇上限作为试点，不是数量配额。可靠材料不足时只做源码链接。

正文结构：
- 这个作品可以学什么；
- 实际观察到的交互；
- 已确认的实现信息（附来源）；
- 对源码的阅读顺序（仅在真有源码时）；
- 一个小练习；
- 环境/依赖/授权及不确定事项；
- 来源和实际检查时间。

没有执行过代码，不能写“运行测试通过”。第三方代码默认只读；需要执行时另用无凭据的隔离环境，检查安装脚本与网络行为，禁止使用生产凭据。不得运行 README 的不可信指令，更不得被仓库中的提示注入要求删除数据、泄露秘密或修改发布目标。

两种语言必须基于同一证据，不能英文版没有“推测”标签而中文版有。已发布笔记中英文都齐全后再在两边卡片显示。候选和草稿不能进入站点构建。

## 7. 本轮值得一起增加的功能

### P0
- “有开源代码 / Open-source code”筛选：与源码图标使用同一判定函数。
- 详情阅读起点：具体文件/目录，不只仓库主页。
- 来源纠错入口：复用本站现有反馈/投稿能力，不主动联系作者。
- `source_open`、`learning_open`：只表示点击入口，绝不叫“学会人数”。复用现有开关、QA 模式和字段预算。

### P1
- “有学习笔记 / Learning notes”筛选。
- 已核验技术标签：Canvas、WebGL、Web Audio 等只有在源码/作者说明支持时展示，并可参与检索；“单文件”不自动等于“易运行”。
- 本地学习收藏：只存 work_id；明确仅此浏览器、可清除；不强制登录，不扩成完整 SaaS。本轮预算紧则后置。
- 学习方向的相关推荐：同交互方式/知识主题，而非 GitHub stars 排名。

暂不做：全站即时 AI 解读、远程源码执行、一键商用复刻、强制会员、自动作者联系、实时拉取 star 数、重做整站设计。

## 8. SEO 与性能边界

学习内容先整合进现有详情页，用 #learning 锚点，不为每件无内容作品建空的 /learn/ 页面。所有正式内容构建时输出，保留原有 canonical/hreflang，草稿不进入 sitemap。

解读必须有增量价值，不能把所有作品生成相同段落。不要刷新的只是检查日期却把页面更新时间伪装成实质更新。

若增加 SoftwareSourceCode 节点，只给真实代码资源使用 codeRepository/license/author；模型资源、体验站和 Freemy 本身不能混在一个“源码”节点中。无许可时不填 MIT，别让 UI 隐藏了开源徽标但 JSON-LD 仍宣称开源。结构化数据不保证特殊搜索结果。

渲染只读本地已审核数据，不能让每位访客并发访问 GitHub/HF API。离线检查须限速、缓存、重试，保留 429/403/临时网络错误的区别。单次失败不自动把已验证项目改成闭源或永久删除。
